# QuickNote 视觉重做 + 勾选框 + 删除 —— 设计定案

日期：2026-10-05
状态：待确认（三处冲突需要使用者拍板）

## 0. 触发这次重做的两个事实

1. **系统是浅色模式**（`AppsUseLightTheme = 1`），所以程序现在跑的是 `Theme.Light()`。
   那个调色板是执行期随手写的、**从未做过 mockup 评审**——深色那套当初给使用者看过，浅色这套没有。
   「丑」的直接来源大概率在此。
2. 使用者装了 Noto Sans SC / 思源黑体 / 等线，不必受制于 Windows 默认雅黑。

## 1. 设计立场

这个东西不是生产力看板，是一块**掉落下来的便签**：双击 Ctrl 出现，写完就走。
它的情绪中心是那两个脸——未完成是灰云出神的脸，完成是派对脸。

因此：**全界面近乎无彩，唯一的颜色来自那两个 emoji。**

这是把「把大胆用在一处」按字面执行。现在的界面用蓝色标标题、橙色标待办，
是在跟 emoji 抢注意力；去掉它们，两个脸才立得住。

（同时避开两个 AI 生成设计的典型特征：米色 #F4F1EA + 陶土色的搭配，以及
纯近黑 + 单一荧光强调色。本方案两者都不是。）

## 2. Token

### Light（当前实际生效的那套，重做对象）

| 角色 | 值 | 用途 |
|---|---|---|
| paper | `#FAFAF8` | 小条底色。近白微暖，**不是**奶油色 |
| ink | `#232326` | 正文 |
| ink-soft | `#55555C` | 次要正文、续行 |
| muted | `#8E8E93` | 键位提示、状态文字 |
| stamp | `#A9A9AE` | 时间戳——比 muted 还轻，让它退到背景里 |
| hairline | `#E8E8E4` | 上下两条 chrome 的分隔线 |

### Dark

| 角色 | 值 |
|---|---|
| paper | `#1A1A1C` |
| ink | `#E8E8E6` |
| ink-soft | `#B4B4B8` |
| muted | `#7E7E84` |
| stamp | `#6E6E74` |
| hairline | `#2C2C30` |

### 颜色的使用纪律

- **标题不用颜色，用字重。** `## 下午计划` 是加粗的 ink，不是蓝色。
- **列表符不用颜色。** 它是结构，不是装饰。
- **行内代码**用 `ink-soft` + 等宽，不加底色（RichEdit 画不出圆角底，方底更丑）。
- 引用行用 `muted`。
- 除 emoji 外，界面没有任何彩色像素。

## 3. 字体

一套 CJK 家族 + 一套数字家族，两者气质明确不同。

| 角色 | 字体 | 字号 | 行高 |
|---|---|---|---|
| 正文 | **Noto Sans SC** | 11pt | 1.55 |
| 时间戳 | **Bahnschrift Light** | 10.5pt | — |
| chrome 上下两行 | Noto Sans SC | 8.5pt | — |

- **Noto Sans SC**：比雅黑 UI 开阔、字面更匀；不是系统默认脸。
- **Bahnschrift Light**：DIN 系，数字有技术感，跟中文的人文气质拉开层次。
  字号要比 CJK 大一档才压得住（Bahnschrift 的 x-height 偏小）。
- 时间戳是**唯一使用第二套字体**的地方——一处就够，多了就乱。

## 4. 布局

```
┌─────────────────────────────────────────────┐
│ 10-05 星期一          今天 3 条              │  ← chrome 上，8.5pt muted
├─────────────────────────────────────────────┤
│ 😶‍🌫️ 14:30  跟老王确认了接口字段             │  ← 正文 11pt ink
│             他那边说字段名改成 snake_case    │  ← ink-soft
│ 🥳 14:32  把 spec 写完                       │
│                                             │
├─────────────────────────────────────────────┤
│ Enter 保存 · Shift+Enter 换行 · Tab 搜索     │  ← chrome 下，8.5pt muted
└─────────────────────────────────────────────┘
```

左对齐，不居中。行高 1.55，给中文一点呼吸。宽度 560 逻辑像素不变。

**分隔线**：上下两条 chrome 各加一条 1px hairline。现在完全没有结构线，
日期、正文、提示挤在一起，这是「乱」的来源之一。

## 5. 光标

「尤其是光标」——现在的光标是 RichEdit 自带的 1px 黑条，按系统闪烁频率跳。

**方案：自绘光标。** `HideCaret` 隐藏系统光标，自己画一根 2px 圆角短竖线，
颜色用 ink、1 秒一循环地柔和明暗（不是硬开关的闪烁）。高度跟随当前行。

这是本方案里唯一一处动效，而且只在输入框获得焦点时存在——待机零开销。

（替代方案 `SystemParametersInfo(SPI_SETCARETWIDTH)` 会改到全系统，
且崩溃后不一定能还原，不采用。）

## 6. 勾选框

### 文件格式

记录行从

```
- 14:30 跟老王确认了接口字段
```

改为

```
- [ ] 14:30 跟老王确认了接口字段
- [x] 14:32 把 spec 写完
```

`[ ]` 在前、时间戳在后——这样 Typora 会渲染成真正的复选框，而时间戳作为
条目正文的一部分保留。

### 读取必须兼容旧格式（重要）

`DateFormat.IsEntryStart` 现在认 `- HH:mm `。改格式后，**使用者现有的
`- 20:18 下载Minimax` 这类旧记录会突然不被识别**——条数归零、上下文错乱、
搜索列不出来。

因此：**写入只用新格式，读取两种都认。**

### 界面显示

勾选框在界面上画成脸，不画成方框：

| 状态 | 显示 |
|---|---|
| 未完成 | 😶‍🌫️ |
| 完成 | 🥳 |

### 空格键的冲突（需拍板）

**空格是正文里最常打的字符。** 直接拿它切换完成状态，就没法打
「hello world」了。可选：

1. **光标在勾选框位置时**（行首附近）空格才切换 —— 保留正常打字，
   代价是要先按 Home
2. **只有空条目时**空格才切换 —— 新建即完成，别扭
3. **换键**：`Ctrl+空格` / `Alt+空格`
4. **鼠标点脸切换**，键盘另给一个不冲突的组合

## 7. 删除

### 冲突：破坏 append-only

spec 第 5 节刻意选了「追加，不重写整个文件」——理由是中途崩溃前面的内容不丢。
删除必须重写那一天的文件，**这条安全性就没了**。

缓解措施（都需要实现）：

- 写临时文件再原子替换，杜绝删到一半文件损坏
- 删除前把当天文件复制一份 `.bak`（当天首次删除时）
- 二次确认：Backspace 进入确认态 → Enter 才真删 → Esc 取消

### 冲突：Backspace 是编辑键

搜索框里的 Backspace 是删字符用的。所以只能**在查询框为空时**才进入删除态，
跟 Tab 是同一类问题。

### 需拍板

- 删一条记录，还是连它的续行一起删？（建议：连续行，否则留下孤儿行）
- 删完停在原地还是关掉小条？
- 要不要给「撤销」？（会显著增加复杂度——需要保留被删内容的窗口）

## 8. 需要使用者回答的四件事

1. **空格键**怎么处理（见 §6）
2. **删除范围**：只删那一行，还是连续行（见 §7）
3. **要不要撤销**删除
4. **emoji 在编辑时也显示吗**：打字时把 `[ ]` 显示成脸，意味着「你打的不是你看的」。
   另一种做法是只在搜索页显示脸、编辑时显示 `[ ]`。

## 9. 影响面

改 `IsEntryStart` 会影响三处，它们都走同一个 helper（这是当初抽它的回报）：
`NoteStore.CountEntries`、`NoteSearcher.ContextFor`、`NoteSearcher.ListRecent`。

删除功能要新增文件的原子重写能力，`NoteStore` 从纯追加变成追加 + 重写两条路径。

## 10. 使用者已拍板（2026-10-05）

### 10.1 勾选只在搜索页做 —— 空格冲突自然消失

**填写页不能勾选。** 空格的冲突因此不存在：搜索页的结果列表本来就是自绘控件
（`SearchResultsView`），不是文本编辑器，空格在那里是自由的。

填写页的规则改为：**每次换行视为一个新的待办项。**

这条改的是数据模型，不只是交互：

```
现在（旧）：Shift+Enter 换行 → 续行，属于同一条记录
            保存后 = 一条记录 + 若干原样续行

改后（新）：Shift+Enter 换行 → 另起一条
            保存后 = 每行各成一条 - [ ] HH:mm 内容
```

也就是说 spec 第 5 节那套「多行内容只有首行带时间戳前缀、后续行原样写入」
的模型，对**新写入**不再适用——那是为「写一段带结构的长内容」设计的，
而使用者的真实用法是「一口气列几件要做的事」。

**但读取仍要兼容旧格式**：老文件里的续行还在，`ContextFor` 不能因此错乱。

### 10.2 删除范围：连续行一起删

删掉一条记录时，它下面的续行（如果有）一并删除，不留孤儿行。

### 10.3 不要撤销，只要二次确认

- Backspace（查询框为空时）→ 进入确认态
- Enter → 真删
- Esc → 取消
- 删前把当天文件备份一份 `.bak`（当天首次删除时）
- 重写走「临时文件 + 原子替换」，杜绝删到一半文件损坏

### 10.4 emoji 在两个界面都显示

打字时打 `- ` 就自动补成勾选框并画成 😶‍🌫️；屏幕上看到的是脸，文件里存的是
`- [ ]`。使用者从未真正手打过 `[ ]`，所以「所见非所打」不构成困扰。

### 10.5 由此产生的键位表

| 界面 | 按键 | 行为 |
|---|---|---|
| 填写页 | `Enter` | 保存全部行，每行各成一条待办 |
| 填写页 | `Shift+Enter` | 换行 = 另起一个待办项 |
| 填写页 | `Tab`（空框） | 切到搜索 |
| 填写页 | `Esc` | 收起，保留草稿 |
| 搜索页 | `Tab` / `Esc` | 切回填写 |
| 搜索页 | `↑` `↓` | 移动选中 |
| 搜索页 | `空格` | **切换选中条目的完成状态** |
| 搜索页 | `Enter` | 用外部编辑器打开那一天 |
| 搜索页 | `Backspace`（查询框为空） | 进入删除确认态 |
| 搜索页（确认态） | `Enter` / `Esc` | 确认删除 / 取消 |

注意 `Enter` 在搜索页是「打开文件」而在确认态是「确认删除」——确认态下
Enter 的语义被覆盖。这是有意的：确认态是个模态瞬间，Esc 能退出来。
